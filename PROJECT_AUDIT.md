## 1. P1: настройки не готовы к публичному развёртыванию

Место: `config/settings.py:28–33`, настройки HTTPS и cookie отсутствуют.

- `ALLOWED_HOSTS = []`: с `DEBUG=False` сайт не обслужит запросы с рабочего домена.
- Не включены `SESSION_COOKIE_SECURE`, `CSRF_COOKIE_SECURE`,

- Обычный `check --deploy` также выдаёт `security.W009` для текущего `SECRET_KEY`.

Подтверждение: `security.W004`, `W008`, `W009`, `W012`, `W016`, `W018`, `W020`.

Исправление: отдельная production-конфигурация либо переменные окружения для

## 2. P1: публичные формы не ограничивают частоту и объём нагрузки

Места: `core/views.py:32`, `core/views.py:130`, `core/forms.py:17`,

Подписанный токен предотвращает повторное создание заявки при повторной отправке

Исправление: общий для процессов rate limiter с HTTP 429, ограничение размера

Параметры лимитов выбрать по реальной частоте обращений.

## 3. P2: UTF-16 SVG обходит часть защитных проверок

Место: `core/validators.py:57`.

Регулярное выражение ищет запрещённые XML-конструкции в исходных байтах, тогда
как `ElementTree` распознаёт UTF-16. В UTF-16 символы разделены нулевыми байтами:
поиск не находит `<?xml-stylesheet ...?>`. Затем XML-парсер отбрасывает processing
instruction, и обход `root.iter()` уже не может её проверить.

Подтверждение: `validate_logo()` принимает следующий файл в UTF-16, хотя та же
конструкция в UTF-8 должна отклоняться:

```python
payload = (
    '<?xml version="1.0" encoding="UTF-16"?>'
    '<?xml-stylesheet href="https://example.invalid/style.css"?>'
    '<svg xmlns="http://www.w3.org/2000/svg"/>'
).encode('utf-16')
validate_logo(SimpleUploadedFile('logo.svg', payload))
```

Подтверждён обход политики запрета внешних стилей. Выполнение JavaScript не
демонстрировалось. Реальное поведение внешних ресурсов зависит от способа
открытия SVG и заголовков; загрузка этих изображений доступна через админку.

Исправление: явно разрешить одну кодировку с проверкой декларации либо применять
XML-парсер, который запрещает DTD/сущности и проверяет processing instructions
независимо от кодировки. Предпочтительно сохранять заново сериализованный
очищенный SVG или растровую версию вместо исходного файла.

## 4. P2: сотрудники с правом просмотра не видят переводы в админке

Место: `core/localization.py:115–118`, `core/localization.py:145`.

Переводы `title_tr`, `body_ky` и прочие добавляются как динамические поля формы,
но хранятся в JSON `translations`. При доступе только для просмотра Django admin
ищет соответствующие атрибуты модели, которых нет, и показывает пустые значения.

Подтверждение: у Page сохранено
`translations={'tr': {'title': 'AUDIT_TRANSLATION_VALUE'}}`. Staff-пользователь
имеет только `view_page`. Страница изменения возвращает HTTP 200, значение есть
в `form.initial['title_tr']`, но отсутствует в HTML. Данные в БД не теряются,
однако сотрудник не может проверить перевод.

Исправление: readonly-accessors для переводов либо отдельное отображение JSON
при отсутствии права изменения. Добавить тест содержимого страницы для
пользователя с `view_*`, а не только проверку HTTP 200.

## 5. P2: повреждённые изображения и PDF проходят валидацию

Места: `core/validators.py:42–51`, `core/career_files.py:32–35`.

Растровые изображения проверяются по нескольким начальным байтам, а PDF — по
`%PDF-` и наличию `%%EOF` в конце. Проверка не устанавливает, можно ли открыть файл.

Подтверждение:

- `validate_logo(SimpleUploadedFile('broken.png', b'\x89PNG\r\n\x1a\n'))`
  проходит, хотя файл состоит только из восьми байт сигнатуры PNG.
- `validate_resume(SimpleUploadedFile('fake.pdf',
  b'%PDF-1.7\nThis is not a PDF\n%%EOF'))` также проходит.

Следствие: сломанные изображения на сайте и нечитаемые резюме у сотрудников.
Такая проверка также не удаляет активное содержимое допустимого PDF; это не
доказательство выполнения кода на сервере.

Исправление: для растра — Pillow verify/load с ограничениями размеров в пикселях,
для PDF — ограниченная по ресурсам структурная проверка PDF-парсером.
Для резюме отдельно рассмотреть проверку на вредоносное содержимое, исходя из
того, как сотрудники открывают документы. Парсер формата сам по себе не является
антивирусом.

## 6. P2: стандартная сборка статики завершается ошибкой

`STATIC_URL` задан, `STATIC_ROOT` отсутствует. Проверка `collectstatic` в dry-run

## 7. P2: параметры БД из `.env.example` частично игнорируются

Место: `config/settings.py:86–94`, `.env.example`.

Переменные `DB_NAME`, `DB_USER`, `DB_HOST`, `DB_PORT` документированы, но
соответствующие настройки жёстко заданы в Python. Из окружения читается только
пароль. Изменение `.env` не перенесёт подключение на другой сервер или другую БД.

Исправление: читать все документированные параметры из окружения, сохранив
разумные локальные значения по умолчанию. Ошибки обязательных production-параметров
выявлять при запуске.
