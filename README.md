# TÜKİD

Многоязычный сайт общественного объединения турецко-кыргызских предпринимателей. Проект объединяет каталог компаний, новости, мероприятия, официальные встречи, приём заявок на членство и вакансии участников объединения.

Контент, переводы, меню и разделы сайта управляются через административную панель Django Unfold.

## Возможности

- **Главная страница:** настраиваемые блоки, логотипы участников, новости, ближайшие мероприятия, встречи и карточки сотрудничества.
- **Каталог компаний:** поиск, фильтрация по сферам деятельности, контакты, связанные новости и открытые вакансии.
- **Информация об объединении:** страницы «О нас», миссия, совет правления, контакты и дополнительные страницы.
- **Новости и события:** категории и теги, отложенная публикация новостей и встреч, анонсы и архив мероприятий.
- **Членство:** электронная анкета, PDF заявки, рассмотрение советом и PDF с решением.
- **Карьера:** вакансии компаний, поиск и фильтры, отклики на вакансии и общие заявки с резюме.
- **Три языка:** русский, кыргызский и турецкий; переводы контента редактируются в админке.
- **Административная панель:** роли и права, поиск, фильтры, массовая публикация, обзор материалов и история изменений.

## Быстрый старт

### 1. Подготовьте окружение

Выполните команды из корня проекта. Для новой установки в Windows / PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

В Linux / macOS:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

### 2. Создайте базу PostgreSQL

Подключитесь к PostgreSQL под пользователем с правами создания ролей и баз. Замените пароль в примере:

```sql
CREATE ROLE tukid_user WITH LOGIN PASSWORD 'change-this-password';
CREATE DATABASE tukid OWNER tukid_user;
```

Если база уже существует, проверьте права пользователя на её схему и создание таблиц.

### 3. Заполните `.env`

```dotenv
DB_NAME=tukid
DB_USER=tukid_user
DB_PASSWORD=change-this-password
DB_HOST=127.0.0.1
DB_PORT=5432
DJANGO_SECRET_KEY=replace-with-a-generated-secret
DJANGO_DEBUG=True
DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1,[::1]
```

Сгенерировать секрет можно командой:

```powershell
.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(64))"
```

Скопируйте результат в `DJANGO_SECRET_KEY`. В Linux используйте `python` из активированного окружения.

### 4. Примените миграции и запустите сайт

```powershell
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py createsuperuser
.\.venv\Scripts\python.exe manage.py runserver
```

В Linux те же команды выполняются через `python manage.py …`.

- Сайт: [http://127.0.0.1:8000/](http://127.0.0.1:8000/).
- Админка: [http://127.0.0.1:8000/admin/](http://127.0.0.1:8000/admin/).

Миграции создают структуру БД и начальный контент. При обновлении существующей установки сначала выполните `migrate`, затем запускайте приложение.

## Настройки окружения

Образцы: [.env.example](.env.example) для разработки и [.env.production.example](.env.production.example) для сервера. Приложение загружает `.env` из корня проекта; переменные окружения процесса имеют приоритет.

| Переменная | Назначение |
| --- | --- |
| `DB_NAME`, `DB_USER`, `DB_PASSWORD` | База, пользователь и пароль PostgreSQL |
| `DB_HOST`, `DB_PORT` | Адрес и порт PostgreSQL |
| `DJANGO_SECRET_KEY` | Секретный ключ Django |
| `DJANGO_DEBUG` | Режим отладки; в production — `False` |
| `DJANGO_ALLOWED_HOSTS` | Разрешённые хосты через запятую |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | Доверенные origin с протоколом, например `https://example.com` |
| `DJANGO_TRUST_PROXY_HTTPS` | Доверие к перезаписанному прокси заголовку HTTPS |
| `APPLICATION_TRUSTED_PROXY_IPS` | IP доверенных прокси для определения адреса клиента |
| `APPLICATION_POST_LIMIT`, `APPLICATION_POST_WINDOW` | Лимит POST и длительность окна в секундах |
| `APPLICATION_GET_LIMIT`, `APPLICATION_GET_WINDOW` | Лимит GET форм и длительность окна в секундах |
| `SITE_CONTENT_CACHE_TIMEOUT` | Срок кеширования меню и настроек; по умолчанию 300 секунд |
| `DJANGO_SECURE_HSTS_SECONDS` | Срок HSTS; production по умолчанию — 3600 секунд |
| `DJANGO_HSTS_INCLUDE_SUBDOMAINS`, `DJANGO_HSTS_PRELOAD` | Отдельное включение HSTS для поддоменов и preload |

Секреты, `.venv/`, `media/`, `staticfiles/` и временные файлы исключены из Git через `.gitignore`. Публикуйте только образцы окружения с шаблонными значениями.

## Управление контентом

Админка работает на русском языке. Через неё можно:

- Настроить название организации, логотипы, favicon, контакты, социальные ссылки и футер.
- Изменить тексты, кнопки, порядок, видимость и количество карточек блоков главной.
- Создавать страницы, редактировать меню и один уровень подпунктов.
- Вести каталог компаний, отрасли, теги и состав совета правления.
- Публиковать новости, мероприятия, встречи с фотографиями и вакансии.
- Рассматривать заявки на членство и отклики кандидатов.

Черновики и материалы с будущей датой публикации скрыты от посетителей. Вакансии показываются только у опубликованных компаний, в пределах срока приёма и при открытом статусе. Для мероприятий учитывается время окончания: текущее событие остаётся в анонсах до завершения.

Сотруднику для входа нужен статус «Персонал» и права на соответствующие модели. Пользователи с правом только просмотра видят исходные сведения и переводы, но не могут изменять записи.

Фотографии поддерживают SVG, PNG, JPG и WebP до 8 МБ, логотипы — до 2 МБ. Favicon также поддерживает ICO. Загруженные изображения сохраняются в `media/`; при отсутствии изображения используются предусмотренные шаблоном заглушки. Форматированный текст очищается при выводе.

## Заявки и документы

### Членство

Посетитель заполняет сведения об организации и представителе, указывает контакты и подтверждает заявление о вступлении. Сервер сохраняет заявку и создаёт PDF на языке подачи.

Совет правления рассматривает заявку в админке. Доступны статусы «Новая», «На рассмотрении», «Принята», «Отклонена». После заполнения служебных полей создаётся PDF с решением; исходные данные и первоначальный PDF сохраняются.

Принятие заявки и публикация компании в каталоге — отдельные действия. PDF формируется ReportLab с локальными шрифтами Noto Sans; документ содержит места для рукописных подписей.

### Карьера

Кандидат может откликнуться на вакансию или отправить общую заявку с желаемой должностью. Форма принимает PDF и DOCX до 5 МБ и сохраняет согласие на обработку данных.

В админке доступны исходные сведения, резюме, название вакансии и компании на момент подачи, статус рассмотрения и внутренние заметки. При удалении вакансии её первоначальное название остаётся в отклике.

PDF заявок и резюме хранятся в PostgreSQL. Скачивание доступно через административные маршруты с проверкой прав; документы не размещаются в публичной `media/`. Резервная копия БД включает эти файлы.

## Локализация

Интерфейс и публичный контент поддерживают русский, кыргызский и турецкий языки. Переключатель сохраняет язык в cookie и переводит на соответствующую страницу с параметрами поиска.

Русские тексты хранятся в основных полях моделей, переводы — в JSON-поле `translations`. Если перевод отдельного поля не заполнен, показывается русский текст. Даты, контакты, изображения и параметры публикации общие для всех языков.

Каталоги интерфейса находятся в `locale/ky/LC_MESSAGES/` и `locale/tr/LC_MESSAGES/`. После изменения `.po`:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe manage.py compile_site_translations
```

Команда проверяет переводы и собирает `.mo` без GNU gettext. Храните `.po` и `.mo` вместе в репозитории. После изменения каталогов перезапустите приложение; правки переводов контента через админку перезапуска не требуют.

## Демонстрационные данные

Для заполнения тестовой установки:

```powershell
.\.venv\Scripts\python.exe manage.py seed_demo
```

Команда создаёт по 10 компаний, членов совета, новостей, официальных встреч и мероприятий с иллюстрациями. Семь мероприятий получают будущие даты, три — прошедшие. Записи отмечены флагом и подписью «Демо»; события, компании и люди вымышлены.

Повторный запуск сохраняет существующие демозаписи и внесённые правки. Обычный контент и заявки команда не меняет. Миграции не запускают `seed_demo` автоматически.

## Безопасность и кеширование

- **Формы:** CSRF, скрытое поле против спама и подписанный идентификатор со сроком действия два часа. Повторная отправка одной формы не создаёт дубликат.
- **Общий лимитер:** атомарные счётчики в БД для всех процессов. По умолчанию на каждую форму с одного IP разрешено 20 POST за 10 минут и 120 GET за минуту. Языковые версии используют общий бюджет; при превышении возвращается HTTP 429 с `Retry-After`.
- **Загрузки:** ранняя остановка слишком большого файла; тело запроса карьеры ограничено 6 МиБ, членства — 64 КиБ. Превышение размера возвращает HTTP 413.
- **Изображения:** SVG только в UTF-8 с проверкой опасных конструкций; растр проверяется Pillow с лимитом 20 миллионов пикселей.
- **Резюме:** проверка структуры PDF и DOCX. Отклоняются активные действия и вложения PDF, зашифрованные PDF, макросы и вложенные объекты DOCX. Проверка формата не заменяет антивирусную проверку.
- **Кеш:** меню и настройки кешируются на 300 секунд с инвалидированием после сохранения транзакции. Язык и активный пункт меню вычисляются для каждого запроса.

Кеш `tmp/site-cache` общий для процессов на одном хосте и должен быть доступен только пользователю приложения. Для нескольких хостов настройте общий backend alias `site_content`. При прямом `QuerySet.update()`, bulk-операциях или SQL инвалидируйте кеш после commit через `core.site_cache.invalidate_site_content()` либо учитывайте TTL.

## Тестирование и CI

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run --settings=config.test_settings
.\.venv\Scripts\python.exe manage.py test core --settings=config.test_settings --noinput
.\.venv\Scripts\python.exe -m pip check
```

`config.test_settings` использует SQLite и хранилище файлов в памяти. Рабочая PostgreSQL этим запуском не изменяется.

Для проверки на PostgreSQL укажите отдельные тестовые `DB_*` и роль с правом `CREATEDB`:

```powershell
.\.venv\Scripts\python.exe manage.py test core --settings=config.test_postgres_settings --noinput
```

Django создаёт отдельную БД `test_<DB_NAME>`. Выдавать `CREATEDB` рабочей роли приложения не требуется.

Тесты охватывают публикацию контента, поиск, формы, документы, переводы, права доступа, миграции, кеш и ограничения загрузок. На PostgreSQL дополнительно проверяется конкурентное соблюдение лимита запросов.

[GitHub Actions](.github/workflows/checks.yml) запускает тесты на SQLite и PostgreSQL, проверяет миграции и production-настройки, собирает статику и выполняет аудит зависимостей через `pip-audit`.

## Развёртывание

1. Создайте серверный `.env` на основе `.env.production.example`, заменив домены, пароль БД и секретный ключ. Установите `DJANGO_DEBUG=False`.
2. Установите зависимости в виртуальное окружение.
3. Примените миграции, проверьте настройки и соберите статику:

```bash
python -m pip install -r requirements.txt
python manage.py migrate --noinput --settings=config.production
python manage.py check --deploy --fail-level WARNING --settings=config.production
python manage.py collectstatic --noinput --ignore=php --ignore='*.php' --settings=config.production
```

4. Запустите WSGI/ASGI-сервер с `DJANGO_SETTINGS_MODULE=config.production`, заданным **в окружении процесса до запуска**. Для management-команд модуль выбирается через `--settings`; одной строки в `.env` недостаточно для его выбора.
5. Настройте HTTPS и обратный прокси по [примеру nginx](deploy/nginx.conf.example). Замените домен, сертификаты и пути, затем проверьте конфигурацию через `nginx -t`.

Каталоги для сервера:

| Путь | Назначение |
| --- | --- |
| `staticfiles/` | Результат `collectstatic`, раздаётся по `/static/` |
| `media/` | Загруженные изображения, раздаются по `/media/` |
| `tmp/site-cache/` | Приватный кеш приложения |
| PostgreSQL | Контент, пользователи, заявки, PDF и резюме |

Пример nginx ограничивает размеры и время загрузок, частоту POST и число соединений форм. Прокси перезаписывает заголовки адреса клиента и HTTPS; доверяйте им только от явно указанных прокси и закройте прямой публичный доступ к порту приложения.

Production-конфигурация требует явных хостов и качественного ключа. Secure-cookie и HTTPS redirect включены. HSTS начинается с 3600 секунд; поддомены и preload включаются отдельно после проверки домена. Уведомления Django W005/W021 об этих двух необязательных параметрах явно отключены, остальные deployment checks выполняются.

Сборка исключает PHP из публикуемой статики, сохраняя исходники и демоматериалы. Шаблон nginx не исполняет PHP. Сжатие и минификация CSS/JS не настроены.

Резервируйте PostgreSQL и `media/`. Для восстановления также потребуются конфигурация окружения и секреты, хранящиеся отдельно от репозитория.

## Сторонние ресурсы

В проект включены сторонний HTML-шаблон, библиотеки, иконки и шрифты с собственными условиями использования. Лицензии Noto Sans и Manrope находятся рядом с файлами шрифтов в `core/fonts/` и `core/static/core/fonts/`.

Общая лицензия для собственного кода проекта в корне репозитория пока не задана. Условия сторонних ресурсов сохраняются отдельно.
